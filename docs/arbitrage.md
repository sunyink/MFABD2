# 商店套利设置

任务按①～⑤依次执行，各阶段可以独立开关。

| 阶段                     | 用途                                             | 默认 |
| ------------------------ | ------------------------------------------------ | ---- |
| ① 开局出售料理，回笼金币 | 出售背包中已达到峰值的料理，供后续采购使用       | 开   |
| ② 低价购入套利材料       | 按低价清单购入材料，可待价转卖或用于料理         | 开   |
| ③ 料理制作               | 用现有材料制作，按需补查库存、补买缺料并尝试补做 | 开   |
| ④ 收尾出售料理           | 出售已有及本轮制作、且达到峰值的料理             | 开   |
| ⑤ 出售多余材料           | 出售达到峰值且超过保留量的材料                   | 关   |

①④使用同一份完整料理目录。③没有勾选制作的料理仍可出售；④关闭时，补做成品留在背包。

## 采购自选

②默认使用推荐采购表。“自定义各卡带采购”开启后，可分别开启每张卡带的“使用自选清单”，再勾选商品。

②常规采购与③材料补买都使用砍价商店，约定购买价为**商品原价减60%**，即原价的40%。先将单价向下取整，再乘数量；例如盐原价18，购买单价为7，400个共2800金币。天赋神药沿用单独计价规则，不套用此折扣。

- 商品初次展开时勾选推荐清单，可直接增减。
- 全部取消表示要求清空该卡带收藏；核对完成后不购买该卡带的任何商品。
- 关闭卡带自选后恢复使用推荐表；关闭外层自定义后，所有卡带恢复使用推荐表。关闭期间忽略子项保存的选择。
- 自选商品只决定②常规采购；③仍可能为料理补买这些商品。
- 天赋神药不提供自选选项，也不会加入采购名单。扫描货架时允许它不出现；出现且已收藏时会取消收藏并复核，未收藏则保持不变。旧配置中残留的天赋神药选择会被忽略。

收藏默认每周核对一次。实际名单改变、首次使用新记录或开启“每次重新扫描购买收藏”时，会重新核对对应卡带，不受本周已扫描限制。核对会取消原有非目标收藏，也会点亮所选商品。

扫描周期由管路中的周检查和完成标记成对管理，在全扫尝试结束后、购买前打标。全扫前撤销旧成功清单，核实成功后逐卡保存；未找到或失败的卡带下次仍会重试。仅名单变化触发的扫描不更新整轮周标记。旧版购买完成标记不作为扫描依据，升级后首次会重新全扫一次。

同名商品可以有多颗星星，每颗分别按采购名单调整：名单内标黄，名单外标灰。扫描使用星星旁的名称区域，并先过滤界面杂字；不要求固定货架格数，也不按商品名称去重。

只有星星与名称明确配对、收藏状态复核正确后，才保存成功记录。某张卡带未找到、识别不明确或点星失败时，仅结束这张卡带的核对，继续处理其他卡带和后续阶段；下次仍会核对未成功的卡带。

“收藏未核实仍继续购买”默认开启。名单读取失败、某张卡带核对失败或未找全时，购买前会提示，并尝试按游戏当前收藏购买。当前收藏可能包含旧收藏或本次已完成的部分调整；例如取消某商品但熄星失败，该商品仍可能被买入。关闭此选项时，未核实则跳过本轮②的一键购买，继续后续阶段；不会强制每次全扫。

单张卡带配置异常只影响该卡带，保留当时的收藏，不自动恢复推荐清单，也不把配置错误当成清空收藏。扫描可以在待尝试项处理完后提前结束，也可以在列表滑到底后结束。存档不可用时停止使用相关记录；成交后的记录失败会提示并正常收尾，不因此重新购买。

## 料理制作与补买

③默认使用推荐制作名单。“自定义制作料理”开启后，checkbox 只决定是否制作该料理；初始勾选为推荐名单，全部取消则跳过整个制作阶段。料理按星级展示，实际执行顺序仍按既定优先级。

“保护稀有材料”默认开启，仍可进一步跳过会与已解锁高位配方争抢材料的料理。

“每周仅执行一次”默认关闭。开启后，整段③每周仅执行一次，包括库存补查、补买和补做。**若同时开启⑤，本周后续运行可能把尚未用于料理的材料作为多余库存出售。**

“缺料时补买并补做”默认开启，与②④独立。它仅考虑所选且未被材料保护禁用的料理；目前要求只缺一种材料、必要库存可确认、预计加工有利润。是否处于今日峰值只限制出售，不限制补买补做。购买后会尝试补做，缺货或无法制作会在日志中说明。

补买的利润判断、购买数量、预计支出、预算分配和单价上限统一使用上述折扣价。执行时再次读取现场单价与总额；现场价格高于本批上限则跳过，不按原价成交。已读取的现场价格不会再次打折，实际支出以购买后的金币差额为准。

“补买利润让出比例（%）”默认10，接受0～100的整数。每份料理的基准多赚＝料理峰值卖价－全配方材料峰值直卖总额－神药成本。每份补买溢价＝为这批料理补买的材料中，高于材料峰值直卖价值的金额，按制作份数折算。跨柜台采购共用同一道料理的额度，不重复让出；不同料理分别核算，低价材料省下的钱不扩大让出额度。

只有每份补买溢价不超过“每份基准多赚×比例”、且最终仍有正收益时才补买。例：每份原本多赚1500，填写10，最多让出150，至少保留1350。0表示不接受溢价，仍可按不高于直卖价值的价格补买；100仍拒绝不赚或亏损。此比例只约束③，不放宽原价减60%的购买上限，也不改变实际出售的峰值条件。

高价柜台超过比例时缩减购买数量，保留可行的便宜部分。缺货或部分买入后，按已确认数量与支出重新核算剩余请求；相关成交或库存无法确认时，取消依赖它的后续补买。回调按每份料理显示基准多赚、允许让出、预计补买溢价及剩余多赚。

本轮②完成一键购买并通过金币核对后，③按默认表和自选覆盖合成的最终采购名单排除已购柜台商品，避免再把每日限量当作剩余供给。②未执行、未确认完成或收藏未核实的卡带不作此推断；其他柜台仍可补买同名材料。

排除已购供给后，同一种材料按柜台单价从低到高补买；不同材料沿料理计划首次出现的顺序安排。每笔回调列出柜台、数量、单价与金额。

常规采购的已购依据缺失或不可用时，③仍按库存和商店现场尝试补买，可能多跑已买空的柜台，部分补买和补做也可能无法完成；补买预算、实际余量和价格约束仍然生效。

“设置补买支出上限”默认关闭：关闭时以当前实读金币为预算，开启时取实读金币和设置金额的较小值。实际只购买计划所需数量，不保证花满预算。**0表示没有补买预算；此上限只约束③，不包括②。**

背包检查按本轮已遍历、且经过用户设置和材料保护后仍获准的料理入口确定所需材料，不要求成功点进配方或做出成品。缺料导致本轮一道料理都没做出时，仍会查库存并计算补买；没有遍历到的入口不参与。已有有效数量会复用，缺少已验证模板的材料保留未知，未知库存不会当作0；补做结束后不追加完整背包扫描。出售时另在商品详情核对库存。

## 多余材料与升级

⑤开启后，默认按14天保留材料，也可关闭“按天数自动保留材料”，改为逐项设置数量。0表示不保留，-1表示全部保留。这里的保留量只限制材料出售，不限制③制作消耗。

行情在①④⑤或③补买实际需要时获取，同一天的完整行情可复用。仅运行②或普通料理制作时不扫描行情；五个阶段全部关闭则直接结束。

升级后请重新核对五个阶段、出售及材料保留设置。原“每种料理仅制作1个”测试选项与追加待售文本名单已移除，不参与新流程。
