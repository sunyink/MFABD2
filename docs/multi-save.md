# 多存档设置

桌面 MFAA 的账号设置位于普通任务 **⚙️ 多存档** 中。

- **启用多存档 = Yes**：使用下面填写的存档号，默认 `0`。
- **启用多存档 = No**：使用默认 `0` 号档，忽略隐藏输入中保留的号码。
- 任务左侧的勾选、全选、全不选和半勾只决定是否运行空入口，**不会切换存档**。无需先执行这个任务，也可以直接运行后面的业务任务。
- 存档号只接受数字。`0` 使用 `agent_save_data.json`，`123` 使用 `agent_save_data_123.json`；前导零保留，`001` 与 `1` 是不同存档。

建议先停止队列，再修改开关或号码。已经开始使用存档的任务会保持原号，下一任务才读取新设置。

## 升级与预设

**升级新增此设置，以及重新应用任务预设后，都默认为 Yes / 0。** 多账号用户请在每个实例填回原来的号码，再启动任务。旧存档文件不会被删除，也不会自动从原来的全局输入复制号码。

应用预设会重建普通任务的选项，因此不能依靠预设保留自填号码。删除“多存档”任务与取消勾选不同：删除会使账号配置缺失；请重新添加这个任务。

输入非法、配置缺失或暂时不可读时，会输出账号错误并停止当前任务，保护已有存档。框架可能仍把这个停止显示为任务完成，请同时查看账号错误日志；后续队列任务不会因此被整体取消。

两个实例主动填写相同的号码，会使用同一份存档。独立账号请填写不同号码。

## Android APK

APK 使用默认 `0` 号档，不显示多存档设置。宿主原有的持久存储目录不变。

旧 APK 如果曾填写非零号码，升级后不会自动读取那份进度；旧文件仍保留，不会自动合并或覆盖默认档。需要迁移时，应先备份并确认来源，避免把其他账号的数据写入默认档。

## 适配与验证

桌面读取 MFAA v2.11.5 起提供的实例身份，再从对应实例配置读取用户输入。其他不提供这项信息的客户端不会被误认为 Android，也不会自动回落到 `0`。

### 源文件与发布产物的形态不同

`assets/interface.json` 里的「启用多存档」挂在 `global_option`，并把号码注入数据节点 `Agt_MultiSave_Inject`。
VS Code 插件（MaaSupport）把全局选项显示在每个任务里、按任务各存一份，单跑一个任务时可以直接在任务里改号。

`install.py` 发布时把它移进「⚙️ 多存档」任务并去掉注入，所以 MFAA 用户只在这一个任务里看到它。
找不到唯一的多存档任务或形态异常时构建直接失败。**判断用户实际看到什么，以 install 产物为准，不要看源文件。**

Agent 按客户端决定来源，不按「哪里有值」：

| 客户端 | 判定 | 存档号来源 |
| --- | --- | --- |
| Android APK | 运行在安卓宿主 | 固定 `0` |
| MFAA | 有 `MFA_INSTANCE_ID` | 本实例配置；不读任何注入值（MFAA 的全局选项是多实例共用的） |
| MFAA 但缺实例 ID | `PI_CLIENT_NAME=MFAAvalonia` | 拦截并提示 |
| 其他客户端 | 以上都不满足 | 本任务注入的号码；没有注入则拦截 |

发布包不含注入，所以用发布包运行的其他客户端（如 MXU）会被拦下，不会落到 `0` 号档。

维护者可运行：

```text
python tools/verify_account_config.py
python tools/verify_account_config_native.py --maa-dir <MaaFw安装目录> --work-dir <临时输出目录>
```

原生脚本使用合成控制器与独立测试 Agent，不连接游戏；它验证任务边界和存储保护，不能代替 MFAA 双实例界面验收。
