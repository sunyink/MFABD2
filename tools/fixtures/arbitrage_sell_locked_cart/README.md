# 未解锁商店识别的离线素材

`sell_list_locked.png` 是 PR #569 的 PlayCover 实机截图（2026-10-21，1280×720）。
它包含活动游戏卡 7、上锁的剧情游戏卡 17–19，以及简体未解锁提示。

2026-10-31 补充 PC 推算适配：现有 PC 商店截图中，卡带缩略图宽度约为原布局的
5/6，列表行距约由 75 像素变为 62–63 像素。据此将 base 的
`Shop/PackLocked.png`（17×24）缩成 PC 的 `Shop/PackLocked_PC.png`（14×20），
使用 Pillow 的 `Image.Resampling.LANCZOS`，保存为 RGB PNG。
独立文件名使 PC 分支只使用这张推算尺寸的模板。

锁图继续借本次选卡的 OCR 命中框定位，偏移由 `[-51,-25,0,50]` 推算为
`[-43,-21,0,42]`。顶部提示 ROI 为 `[320,105,640,80]`：高度按约 5/6 估计，
水平方向围绕屏幕中心留宽。阈值 0.8 沿用原分支。

简繁提示分别匹配以下文字：

- 简体：`{0}游戏卡尚未解锁，无法使用商店功能。`
- 繁体：`{0}遊戲卡帶為鎖定狀態，無法使用商店。`

`{0}` 是可变卡带名；识别词省略这个前缀和末尾句号，用 `.*` 容纳句中标点。
base 和 PC 同时保留简体、繁体两条模式。

运行 `python -B tools/verify_arbitrage_sell_locked_cart.py -v`：PC 用例将原截图按
5/6 缩成 1067×600，再放入 1280×720 黑色画布左上角。原图和 PC 模板分别缩放，
测试使用真正的 base + PC 资源加载和 MaaFramework 识别。
覆盖三张锁卡的锁图出口、单独的简体提示出口、相邻可用行不误认锁、正常选中优先于
残留提示，以及覆盖后退出路由的继承。

这份合成画面只验证推算尺寸下的识别与路由。PC 锁卡画面的模板得分、提示位置、
繁体实际 OCR，以及真实出售/补买的完整返回流程，仍需实机核对。

2026-10-31 在 MaaFramework v5.14.3 上，15 项回归全部通过，无跳过；ADB、PlayCover、
PC 三种资源组合加载通过。另外对已有四张 PC 商店截图中的同一组可用卡带做原生模板
回放，在 `[150,80,62,640]` 整列区域搜索，最高匹配分数为 0.534292，未达到 0.8。
这四张截图的左侧卡带内容相同，不计作四组独立场景，也没有补足 PC 锁卡正样本。
